## 闭环具体验证了什么

1. **漂移监测**：把当前公开验证输入与 train 建立的固定参考比较，记录 PSI、分箱距离和均值偏移。A/B 四轮均告警，C 四轮均未告警；没有把 C 的正常监测结果写成发现漂移。
2. **诊断归因**：在授权公开标签上分析 A 的弱类别、混淆，以及 B/C 的误差方向、寿命分段表现，形成待实验验证的解释。统计线索不等于已证明物理故障原因。
3. **实验优化**：真实 27B 阅读历史、诊断和门槛，从代码限定的菜单中选方案；程序从实际父模型续训，继承权重、优化器和标准化，生成候选。没有让模型任意生成训练代码。
4. **评估上线**：候选通过本地检查后经 SDK 上传，由模拟宿主执行独立预测测量，再将真实测量返回 27B 选版。A 要求 Macro-F1 至少增加 0.0005，且支持数至少 20 的类别单步召回下降不超过 20 个百分点；B/C 要求 RMSE 降低至少 `max(1e-6, 父 RMSE×0.0005)`，MAE 相对增加不超过 2%。结果不合格不能被 AI 理由覆盖。
5. **历史回滚**：正常阶段结束后进入预设故障场景，让真实 27B 依据历史和当前测量决定回退。执行 SDK 取回历史文件，再在当前公开验证集复评；下一轮检查完整父产物清单和摘要确实继承。

故障只施加在隔离的模型副本上：A 循环置换输出类别；B/C 将输出偏置增加 10 个标准化目标单位。没有修改原始模型、原始样本或标签。该测试验证规定故障下的恢复路径，不等于自然隐藏数据流上的全面验证。
