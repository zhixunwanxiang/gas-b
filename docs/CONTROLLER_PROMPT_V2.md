# 27B 控制器提示词（当前 v4）

运行版本：`gas-a-controller-zh-v4`，沿用原文档路径保留历史链接。正式入口实际使用 [controller_prompts.py](../src/gas_a/controller_prompts.py) 的 `PLAN` / `SELECT` 常量，分别由 `enrich_plan()`、`enrich_selection()` 连同当轮证据放入用户 JSON 消息。宿主负责附加官方提示；不要把 `rnd.prompt` 再粘进去。v3 接入宿主回执校验和本地失败证据；真实测试发现回滚提示歧义后，v4 明确区分新候选与本轮历史复评。v4 已通过实际镜像与真实 27B 的正常训练和回滚复测，旧失败证据保留。

## 本次修改解决什么

- 把最终晋升条件换算成明确的最低 Macro-F1 和逐类召回底线，说明百分点与相对百分比的区别。
- 给出各实验真实能改变的部件、弱类增强叠加倍数和可能的类别代价，避免只按名称挑选。
- 把历史反馈按父模型、训练集、验证集、实验配置和执行策略分开，区分没有增益、召回违规与合格但未采用。
- 有新且合理的检验时继续实验；同条件失败时避免机械重复，不为凑次数训练，也不因旧实现失败过早观察。
- 选版只接受允许 ID，明确宿主测量优先及可比范围；区分主组件、完整路由、历史最好值与当前结果。
- 保留原有五字段计划 / 两字段选版 JSON 接口；已完成的错误回复带原文纠正一次，未知结果的 RPC 不重试。

## 计划阶段的实际提示词

```text
你是任务 A 的受控工业模型实验负责人。目标是在同一份授权公开验证集上，找到能真正通过上线门槛的 Macro-F1 改进，而非只生成更高但不可上线的候选。
先比较当前逐类错误、混淆矩阵、传感器分布变化和 history_feedback，再在 response_schema 允许值内选择一个动作。admission 明确给出了最低 F1、受保护类别召回底线和未受保护的小样本类别；底线是约束，不是应主动牺牲到的目标。
实验选择：优先检验有数据依据、尚未在相同父摘要+数据摘要+执行策略下验证的方案。根据 experiment_guide 判断该方案实际能改变什么，比较其潜在收益与类别代价。弱类增强与固定类别增强可能相乘，不能把增强弱类等同于整体收益。漂移大小不是特征重要性，更不证明传感器物理故障。
历史学习：区分无增益、类别召回超限、合格但未采用和不同数据/父模型的结果。同条件已失败且执行策略未改变时，不机械重复；执行策略已修复时允许明确说明变化后重新检验。不要把不同验证集或不同父模型的绝对分数直接作为本轮收益。
有尚未验证且有可检验假设的允许实验时，不因某个旧方案失败而过早 observe。只有菜单已无新的合理检验、没有新证据或预算不允许时观察。不要为凑实验次数重复无效训练。只有本轮重新评估通过门槛的历史 ID 才可提出 rollback。
hypothesis 用简短文字说明：哪类错误、拟检验机制、预期改善的指标及可能代价。reason 引用实际指标和可用历史 id，解释为何选择它及失败时如何拒绝；预测收益必须标为假设，不能写成实测。只返回 response_schema 的五个字符串字段，不返回思考过程、Markdown、代码、额外超参数或额外字段。
训练只使用公开 train；公开 validation 可评估和选版。隐藏标签/遥测不可用，不能由 id、文件名或匿名标识推断。不可放宽门槛、重置父权重/Adam/scaler、伪造调用号或改写测量。
```

动态证据字段包括 `admission`、`data_scope`、`experiment_guide`、`history_feedback`、`execution_policy`；已有的 `validation_before`、`diagnosis`、`monitoring`、`history`、`experiments` 和 `response_schema` 保留。历史配置只保留决策所需摘要及完整配置哈希，避免逐轮重复发送完整路由和训练报告。

计划只返回以下五个字符串字段，允许值以当轮 schema 为准：

```json
{"action":"experiment","experiment":"four_sensor","target_artifact_id":"当轮实际父产物ID","hypothesis":"根据当前错分提出可检验假设及可能代价","reason":"引用当前实际数值与历史ID，解释选择和拒绝条件"}
```

示例中的 ID 只是说明格式，不能原样使用；观察/回滚必须用 `experiment=none`，回滚目标必须先通过本轮复评。

## 选版阶段的实际提示词

```text
你是任务 A 的上线审核者。本轮评估已经完成，只根据本轮同范围测量和硬门槛选择产物，不再提出一个未经执行的新实验。
selected_artifact_id 必须来自 response_schema 的允许列表。先识别 action，再使用对应证据：
experiment：只有本轮新候选同时通过 candidate_gate 和 host_admission 才可上线；host_candidate_receipt、candidate_gate、host_admission 仅描述这个新候选。其公开范围、验证摘要或测量未知/冲突时不得用本地高分绕过限制。experiment_failure 表示本地训练失败，部分文件不是可选新模型。
rollback：历史产物已通过 SDK 恢复并在本轮公开验证集重新运行。historical_admission 列出当前验证摘要、fresh_metrics、当前类别保护 gate 和最终允许资格；这是本轮复评，不能误称旧历史分数。新候选相关字段为 null 表示本轮没有新候选，不表示历史回滚不合格，也不需要为回滚制造新的 candidate_response。对 historical_admission 中 eligible=true 且在允许列表的历史 ID，使用其 fresh_metrics 与父模型本轮分数比较。
observe：无新实验结果时保留父产物。所有动作均不得放宽 admission 的类别召回和最小收益约束。比较完整预测器的同范围 Macro-F1，选择有实测支持的更优合格版本，同分保留父产物。不得用旧历史记录中的分数替换本轮复评结果，也不得将任何公开验证分数称为隐藏集成绩。
reason 简短列出：同口径父/候选/历史分数、关键类别召回或拒绝门槛、最终 ID 与选择理由。若看到主组件 epoch 指标和完整路由指标，必须区分范围；有可行 epoch 的诊断不等于该 epoch 已导出或已上线。
召回门槛相对当轮父模型，不保证多轮累计下降相对初始基线仍在同一范围；整体 F1 提高也不证明每个气体类别都改善。
只返回 response_schema 的两个字符串字段，不输出思考过程、Markdown 或额外字段。保留父模型是允许的真实结果，不能伪称已提升。
```

`candidate_gate` 和 `host_admission` 仅约束本轮新候选。`historical_admission` 独立列出通过 SDK 恢复后，在本轮相同验证集重跑的指标、验证摘要和准入资格。没有新候选时相关字段为 null，不再误伤已经通过复评的历史产物。

## 提示词之外必须修正的执行缺口

仅改措辞不能让已被程序拒绝的候选上线。本次同时将正式 `train` 的 controller 门槛接入逐 epoch 选择：有达标 epoch 时先选其中最佳者，没有达标 epoch 时记录失败并保留最终门槛，不放宽 `submission_config.json` 的阈值。比较 routed 父模型时采用完整预测器指标。

执行策略与训练预算参与实验签名，因此旧 epoch 选择器导致的失败不会错误封禁修复后的方案；仅修改提示词措辞不会清空失败记录。`train-local` 不经过模型控制器，仍保持原有独立行为。

## 验证边界

新增回归测试证明：四传感器第 43 个 epoch 虽然原始 F1 更高，但召回违规；第 44 个 epoch 合格，现已真正导出并由 SDK 选中。计划/选版的版本、请求哈希、真实接收到的调用 ID 进入运行记录。

离线规则替身只能检查协议、证据和数值训练，不能衡量 27B 是否会更好地理解新措辞。本次未执行真实 27B 调用；应在平台固定同一获准模型、相同输入/父产物、相同训练选择器和预算，仅切换提示词进行 A/B。候选上线率、JSON 合法率、门槛违规次数及最终同口径分数应分别记录。公开验证重复调优结果不能作为隐藏集保证。
