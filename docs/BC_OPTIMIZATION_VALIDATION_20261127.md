# B/C 优化实现与公开验证记录（2026-11-27）

基于 `codex/main-20261127` 的 `0c0ba6f` 工作区实施。实际参与实验的代码由各输出目录的 `registration.json` 中逐文件 SHA-256 标识；这些工作区改动尚未提交。项目 A 的训练、模型和配置未调整。

## 已实现的改动

1. **完整验证指标**：B 按轴承分组；C 按 `source_subset/source_split/unit`、FD 来源及六个名义工况分组。增加等设备平均 RMSE、P99/最大绝对误差、平方误差贡献、NASA 高估/低估贡献及最差 1% 样本贡献。RUL 段边界继续使用首次训练集分位点。未知元数据明确归为 unknown。
2. **一致准入**：逐 epoch/修正强度选择、最终候选和历史恢复共用 RMSE/MAE 门槛；C 新增 NASA 相对父模型最多增加 5% 的保护。5% 是本项目的可配置策略参数，并非比赛评分公式；它是逐步约束，不代表整个运行期间 NASA 相对初始版本最多增加 5%。NASA 溢出不截断成较小分数。
3. **独立实验账本**：训练完成且本地拒绝的候选不再上传，但仍记为真实完成的性能拒绝。账本与 SDK artifact ID 分离，不伪造产物或宿主回执。同父权重、数据、方案和执行版本的已完成性能拒绝只运行一次；超时与测量未核验不直接套用这一规则。
4. **借鉴 A 的证据组织**：规划请求增加实验能力说明、当前条件下的历史证据、数据范围及风险；元数据只用于分组和 train 权重，不作为预测输入。控制器只接收误差最高的八个设备组，完整指标保存在状态及训练报告中，避免撑大 SDK 配置和提示上下文。
5. **B 加权训练**：轴承频数的逆 0.25 次方加权，权重均值归一化为 1。它与普通 MSE、Huber、新结构分别运行，不强制组合。
6. **B 模型结构**：在冻结完整父模型的前提下，使用有符号 log1p 特征、三个频带占比和水平/垂直差值构建 57 维特征，拟合带正则的线性残差修正。新层有自己的 train 均值和标准差，保留父模型全部 scaler 和 Adam 状态。
7. **C 加权训练**：train 的上四分位寿命段乘 1.5，整体权重均值归一化为 1；不截断真实 RUL，也不把目标寿命用于推理路由。
8. **C 模型结构**：只按合法 settings 识别六个名义工况；组合全局输入、工况局部传感器标准化、工况指示及局部交互得到 177 维特征，拟合带正则的残差修正。小组统计向全局收缩；未匹配工况只走全局特征部分。统计量全部来自 train。
9. **Huber 标定**：delta 使用父模型在 train 上的标准化绝对残差 80% 分位点，限定在 [0.1, 2]；不使用 validation 拟合 delta。
10. **完整模型生命周期**：单文件 NPZ 保存 NN、Adam、scaler、新层参数、独立统计量及训练来源。复合格式会被原始 MLP 加载器明确拒绝，避免静默丢层。新增层最多两层；零强度层与父预测逐位相同。新增层训练时冻结全部父组件，后续 NN 续训按包含已有修正层的整体误差求梯度，已有修正层保持冻结。导出后重新加载并校验完整预测一致。

尚未接入原始波形网络、时序网络、分位数输出、多种复杂树模型的大规模搜索。当前接口只提供单点 34/24 维输入，前两项需要额外的合法输入接口；其余方案需要独立实验依据。也未根据仅三个 B 验证轴承直接设置硬性的设备零退化门槛。

## 验证方式

使用项目 `.venv` 的 Python 3.12.13、NumPy 1.26.4 和 SDK 1.0.4。实验不覆盖原始基线或公开数据，候选产物仅保存在 `runtime/`。

- **独立消融**：每个任务六个候选均从同一官方初始 checkpoint 出发，参数和统计量仅拟合 train。每个候选通过真实 `harness.py predict` 进程逐行预测，并与内存中的完整模型比较，验证门槛一致。来源身份、数据分布、逐样本预测、分组指标、训练报告和耗时均留档。
- **十轮 SDK 闭环**：B、C 各十轮，显式使用离线模型替身，但运行真实数值训练和 SDK 帧、上传、回执、保存状态、父产物继承及原生预测。每个任务三次上传、七次本地拒绝；均引用实际读取的历史并完成 finish 确认。该测试不构成真实 27B 或正式隐藏测评。
- **97 项相关测试**：覆盖 B/C 原生输入、梯度续接、冻结状态、复合模型保存/恢复/下一轮续训、NASA 方向与溢出、NASA 准入、相同实验去重、数据投影变动、SDK 身份核验、历史隔离、RPC 中断、配置限制、启动及访问审计。

## 结果与取舍

以下比较使用同一公开验证集：B 1,679 行、C 23,049 行。此前十轮结果来自 `runtime/fresh-multiround-a-current-bc-v18-20261126/`，本次来自 `runtime/bc-optimizations-sdk-20261127/`。两次从相同官方初始检查点出发，实验菜单不同。

| 指标 | 此前当前分支十轮 | 本次十轮 | 变化 |
|---|---:|---:|---:|
| B RMSE（分钟） | 651.626661 | 623.295585 | 降低 4.35% |
| B MAE（分钟） | 539.823027 | 518.803603 | 降低 |
| C RMSE（循环） | 51.614535 | 50.929263 | 降低 1.33% |
| C MAE（循环） | 38.043047 | 37.377500 | 降低 |
| C NASA（逐行求和） | 3,370,559,951.75 | 3,106,349,749.16 | 降低 7.84% |

独立消融中，B 最低合格 RMSE 为 **612.299011**（`bearing_log_ridge`）；C 为 **50.582760**（`cmapss_condition_ridge`），对应 NASA 为 **4,747,394,603.06**。这两组是不同训练路径的独立实验，不能把该 C 的较低 RMSE 和十轮结果的较低 NASA 拼成一个模型的成绩。C 独立最佳模型的 NASA 相对官方初始基线改善，但比此前十轮最终模型差，因此不能宣称该候选全面优于此前版本。

本次 C 第 2 轮中，RMSE 从 51.827464 降到 51.756637，但 NASA 从 3,752,741,288.42 升至 4,528,567,324.41；新保护将其本地拒绝。第 5 轮尾段加权把 NASA 降到 2,619,929,903.65，但 RMSE/MAE 未过门槛，同样未采用。这验证了多指标之间的实际冲突，说明不能默认把所有训练改动叠加。

**仍存在分组退化**：B 的 Bearing1_4 RMSE 从此前的 274.40 升到本次的 300.00，约恶化 9.33%；总体收益主要来自占验证集 90.23% 的 Bearing3_4，其 RMSE 从 678.93 降到 647.95。B 的设备加权单独运行也未胜过普通低学习率方案。当前结果支持总体公开 RMSE 改善，不能据此断言跨设备泛化已改善。

C 的 FD004 仍贡献约 97.24% 的 NASA，最差 1% 样本贡献约 97.18%；高寿命段低估问题仍在。NASA 的指数尾部和只有少量独立设备的 B 验证集，均需要后续按设备留出验证；预训练父模型已经见过的 train 设备不能当作整个模型的全新设备测试。

十轮运行本机墙钟耗时 B 约 15.42 秒、C 约 119.72 秒，数据集并行运行且包含本地宿主/原生预测开销。这些时间不代表容器预算、真实模型调用费用或正式资源分。NASA 仍按公开投影全部周期求和，不与官方截断 test 的每台发动机末端一条协议混比，也不与实验报告中不同隐藏样本量的数值直接比较。

## 后续实现与复验

B 的设备保护覆盖公开验证中至少有 30 条记录的已知轴承。每次晋级允许的单轴承 RMSE 增量取 10 分钟和当轮父模型该轴承 RMSE 的 5% 中的较大值。该参数由本次实验设置。验证记录不完整的设备显示为 unknown。C 继续使用 RMSE、MAE 和相对当轮父模型的 NASA 上限。

- 用 `run_fresh_multiround.py --regression-order configured` 复现当时两项目均按原配置顺序的对照。用 `--regression-order mlp-first` 复现两项目均优先运行 MLP 的对照。用 `validate_regression_generalization.py --ablations` 复现固定设备划分的特征、方向损失及工况消融。

## C 的限幅残差修正

C 首轮仍优先做条件残差 MLP。当父模型已有两层普通修正时，后续实验菜单提供 `cmapss_bounded_residual`。该实验冻结完整父模型，用公开训练数据拟合 NumPy 残差头。它限制单条样本的残差幅度，并在原预测已较高时逐渐减小向上的修正。新的检查点包含完整父权重和修正头。该方案只有在同一公开验证集上同时改善 RMSE、MAE 和 NASA，且通过 SDK 宿主核验时，才能采用。采用后冻结对应父权重，训练投影更新时再重拟合限幅头。106 项测试通过。默认离线 SDK 路线第 8 轮采用该检查点，第 9、10 轮继续使用，组件验证与十轮选中的检查点 SHA-256 一致。
