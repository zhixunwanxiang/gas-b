# 项目 A：平台十轮报告修复与 v11 交付

2026-11-25。依据用户提供的 `D:/liyue/工业模型赛题研究/实验报告A.txt` 排查并修改。本文及测试均不把报告中的候选分数当作已上线成绩。

## 报告暴露的问题

十轮始终选择 `baseline-cpu-a-guide-20261110-v1`。第 1、3、7、9、10 轮均出现“本地候选通过，但 `parent_measurement_unverified` 阻断”；后两轮候选约 0.90，实际仍保留父模型。第 2、4 轮还有独立的乙醇召回降幅超限问题。第 5、6、8 轮观察不能解决测量兼容问题，历史恢复也受到父测量不可比的影响。

报告未提供原始 start 帧，不能据此确定真实宿主究竟缺少哪个元数据字段，也不能排除分数冲突。本次在旧镜像上复现了一种足以造成同样阻断的情况：`current_validation` 提供具名指标，但没有可选的 `scope`、`validation_sha256`。旧代码仅为候选回执补充当前 SDK 事务身份，未为父模型精简摘要提供同类核验。

## 实现

1. **当前父测量绑定。** 仅在 A 的当前 SDK 会话中，将 `start.current_validation` 与实际父产物 ID、主检查点摘要、当前公开验证文件摘要和本轮身份绑定。父模型的完整预测器先经 SDK 文件清单校验并在当前验证集实测，宿主分数仍须在 `1e-6` 容差内与实测一致。保留原始宿主分数和摘要，不补写原始回执，不从历史配置恢复绑定。
2. **冲突继续拒绝。** 显式隐藏范围、错误验证摘要、错误父 ID/摘要/数据集/轮次、非法指标及宿主与本地分数冲突，均不能获得采用资格。无测量时的既有本地父参考规则保持不变。
3. **保护类别的路由搜索。** 路由校准使用完整实际父预测器作为比较基准，优先选择通过现有 F1 与类别召回门槛的策略。增加外层融合权重菜单 `[0.25, 0.4, 0.6, 0.8]`，提供较轻的融合选择；有合格路由时，不会被更高 F1 但乙醇召回超限的路由取代。若全部不合格，仍如实记录并由最终门槛拒绝。
4. **规划识别兼容性拒绝。** 提示中加入当前父核验状态和实际路由菜单；测量兼容性失败与训练无收益分开解释。宿主准入和路由执行策略版本进入实验指纹，使修复后的实验可重新检验，旧失败记录保留。

最小 Macro-F1 增益仍为 `0.0005`；支持数至少 20 的类别单步召回降幅上限仍为 `0.20`。权重、Adam 状态、scaler、seed、平台 SDK 与原模板没有被重置或替换。训练梯度仍只使用公开 train，validation 用于测量和选择。

使用原始 A 公开包、SDK 1.0.4 与实际镜像预测进行本地宿主对照。两组均人为省略 start 和候选摘要中的可选身份字段，以具名宿主实测指标返回；这是兼容场景复现，不是取得了组委会原始帧。

|---|---:|---:|
| 轮数 | 4 | 10 |
| 初始公开 Macro-F1 | 0.7140297221 | 0.7140297221 |
| 第 4 轮选中模型 Macro-F1 | 0.7140297221 | 0.8058813363 |

新版第 1、2、4 轮采用候选，其余轮次无足够收益而保留当前模型。10 轮均继承实际选中产物、保存状态与已读历史，并收到完成确认。累计启动 10 个训练容器和 21 个预测容器；禁网、只读根目录、非 root、2 CPU、4 GiB 的运行策略核验通过。

A 独立交付快照 **193 项测试通过**。新增回归覆盖精简父摘要、显式冲突拒绝、父模型/验证文件摘要检查、真实 SDK 候选采用、精简父摘要下的历史回滚，以及“高分但乙醇召回超限”与低权重合格路由的取舍。工作区当时的全量 202 项测试也通过，其中包含其他并行任务的测试，不计入 A 独立交付数量。

验证模型决策使用离线替身，新增付费模型调用为 **0**。公开数据与数值训练真实执行，未获取隐藏数据；上述结果不等于组委会正式复测或隐藏集成绩，也不能承诺报告后期漂移数据上的 0.90 候选一定可采用。

## 类别收益与剩余限制

最终公开乙醛召回从 0 提高到 **98.17%**，乙醇精确率从 **53.02%** 提高到 **80.52%**。乙醇召回从 96.34% 降至 75.61%；各次采用满足相对当轮父模型的单步保护，但相对最初基线的累计降幅超过 20 个百分点。规则没有增加累计基线保护。

公开甲苯仅 5 条，不受 `minimum_class_support=20` 的硬保护；本次其 F1 从 0.6667 降至 0.1633。这份交付改善整体 Macro-F1，并不代表每个类别都提高。正式后期甲苯低召回仍需新的授权验证证据检验，不能用这 5 条样本推断隐藏阶段表现。

若正式平台仍出现父核验失败，应查看上传状态 `decisions.jsonl` 中 `host_admission.parent.reason` 及保留的原始 `host_parent_validation`，区分身份缺失、显式身份冲突与分数冲突；不能直接关闭门槛。
